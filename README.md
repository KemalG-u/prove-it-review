# prove-it-review

An agent skill and a reviewer subagent definition for checking plans, other agents' reports and your own work by trying to break them, with a small calculator for what "0 errors in n samples" really tells you.

## What it does

AI coding agents report "done" with confidence, and the report is easy to believe. This project gives an agent (or a person directing agents) a short, strict procedure for not believing it without evidence:

- The **skill** (`skills/prove-it-review/SKILL.md`) covers three situations: a plan about to be executed (write basis, assumption, refutation and rollback for each step, then attack it), another agent's delivery (split every claim into `VERIFIED`, `FALSE` or `UNVERIFIED`, run the main claim for real, tie acceptance to a version of the output) and your own work (look for how it could be wrong before showing it). Findings use a fixed format: verdict, scope, evidence, severity, skipped checks, suggested fix. A table of "excuses" (for example "the tests pass", "0 errors in the sample") says what to do instead of accepting them.
- The **reviewer subagent** (`agents/prove-it-reviewer.md`) is a Claude Code subagent definition with read, search and shell tools that preloads the skill, for a review in a clean context.
- The **calculator** (`skills/prove-it-review/scripts/sample_bound.py`) turns "no failures in n random samples" into an upper bound on the failure rate instead of a claim of zero.

What it does not do: it does not run by itself, it does not make a reviewer independent of the producer (a clean context on the same model is still the same model), and it is no guarantee that work is correct. It is a checklist with a format, not a verifier.

## Install and run

Requirements: Python 3 (tested on 3.12) for the calculator, the example and the tests. Dependencies: none (standard library only). The commands use `python3`; on Windows use `python`.

See what "0 failures in 40 samples" allows you to claim:

```
python3 skills/prove-it-review/scripts/sample_bound.py 40
```

Expected output:

```
n = 40, 0 failures observed
95% upper bound on the failure rate: 7.2%
3/n approximation: 7.5%
Valid only if the sample was random and independent; not for hand-picked hard cases.
```

A worked example is in [`examples/`](examples/): a synthetic report ([`agent-report.md`](examples/sample-delivery/agent-report.md)), the code it describes, and the review the skill produces ([`review-output.md`](examples/review-output.md)). The commands the review cites are run by the tests.

The skill folder `skills/prove-it-review/` is self-contained: it includes the calculator (`scripts/`) and the reference notes, and the links in it that lead elsewhere in this repository are absolute GitHub URLs, so copying only that folder (as below) loses nothing.

### Claude Code

1. Copy `skills/prove-it-review/` to `.claude/skills/` (this project) or `~/.claude/skills/` (all projects).
2. Optional, for a review in a separate context: copy `agents/prove-it-reviewer.md` to `.claude/agents/` or `~/.claude/agents/`. The definition does not set a model; set `model:` yourself so the reviewer is at the producer's level or higher (see [`references/hosts.md`](skills/prove-it-review/references/hosts.md)).

### Codex

Copy `skills/prove-it-review/` to `.agents/skills/` in your repository or `~/.agents/skills/` for all projects, and call it by name (`$prove-it-review`) or let the description match. The subagent file is Claude Code only. The skill has not been loaded in a live Codex session by the author.

## Limits

- **A skill is advice.** The agent can skip it; nothing enforces it.
- **Same model, same blind spots.** A reviewer built on the same model as the producer shares its failure modes. The skill says to name that level honestly ("same model, clean context").
- **Read-only is intent.** The reviewer definition limits tools to Read, Grep, Glob and Bash. Bash can run commands with side effects; the definition tells the reviewer not to, and nothing enforces it.
- **The calculator is narrow.** It covers zero observed failures in independent, random samples. It says nothing about hand-picked cases or about samples with failures.
- **The excuses table is distilled experience.** Its origin is the maintainer's own work with agents; the underlying incidents are not published and cannot be checked here (see [docs/AI-USE.md](docs/AI-USE.md)).

## How it was built

This is a generalised extraction of a skill and a subagent definition from the author's own private agent setup, prepared for publication on 2026-11-18. The extraction removed personal rules, paths and incident records, rewrote the text in English, added the calculator (the original text quoted a formula without a script), a worked example whose commands are tested, and the documentation. It was written with Claude Code under the author's direction; what the human did, what the AI did and what was not verified are stated in [docs/AI-USE.md](docs/AI-USE.md).
